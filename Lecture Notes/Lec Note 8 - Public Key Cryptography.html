Public Key Cryptography

How two people who have never met can agree on a secret in public, how RSA turns the difficulty of factoring into a lock anyone can close but only one person can open, and how the same idea gives us digital signatures.

1. Why public key 2. RSA 3. Diffie-Hellman 4. Signatures 5. ElGamal, DSA & ECC 6. In practice Takeaways

Where this fits. Last lecture ended on the biggest weakness of secret key cryptography: before Alice and Bob can talk securely, they must already share a key, and they need a secure channel to share it. Public key cryptography breaks that circle. Each person gets two mathematically linked keys, one they publish to the world and one they never reveal.

The ideas build on each other: why two keys solve the distribution problem, the modular arithmetic that makes it possible, the RSA algorithm, the Diffie-Hellman key exchange (and the attack it is vulnerable to), digital signatures, the discrete-log and elliptic curve family, and finally how real systems like TLS combine public key and secret key cryptography.

01

Why public key cryptography

Two keys instead of one: a public key anyone can use, and a private key only its owner holds.

Definition

Public key cryptography, also called asymmetric cryptography, gives each user a key pair: a public key e that can be shared with anyone, and a private key d that is kept secret. What one key does, only the other key can undo, and knowing the public key does not let you work out the private key.

The everyday analogy is an open padlock. Bob manufactures padlocks and hands out open ones to anyone who asks, but he keeps the only key. Alice puts her message in a box, snaps one of Bob's padlocks shut, and sends the box. Eve sees the padlock travel one way and the locked box travel back, but neither helps her: closing a padlock is easy for anyone, opening it needs Bob's key.

The key distribution problem, counted

With secret key cryptography, every pair of people who want to talk privately needs their own shared key. That grows quadratically. With public key cryptography, each person needs exactly one key pair, and anyone can encrypt to anyone. Drag the slider to see the difference.

Confidentiality

Encrypt with the recipient's public key. Only the recipient's private key can decrypt it.

Digital signatures

Sign with the sender's private key. Anyone can verify with the sender's public key, and nobody else could have produced it.

Key establishment

Two parties derive a shared secret key over a public channel, then switch to fast secret key cryptography.

The catch

Public key algorithms are much slower than secret key algorithms, typically by several orders of magnitude. And publishing a key creates a new problem: when you receive "Bob's public key," how do you know it really belongs to Bob? Both points come back in sections 4 and 7.

RSA

Rivest, Shamir and Adleman, 1977: the first widely used public key algorithm, and still everywhere today.

RSA can do both encryption and digital signatures. Its security rests on the fact that multiplying two large primes is easy, but recovering the primes from their product is not.

The RSA algorithm

Public key: (e, n)  ·  Private key: (d, n)

Encrypt message m (with 0 ≤ m < n): c = me mod n

Decrypt: m = cd mod n

Why decryption works

Since e·d ≡ 1 (mod φ(n)), we can write e·d = 1 + k·φ(n) for some integer k. Then cd = med = m · (mφ(n))k ≡ m · 1k = m (mod n) by Euler's theorem. (A short argument using the Chinese Remainder Theorem shows it also holds for the rare m that share a factor with n.)

Notice the decrypted value always equals the original message, and that the ciphertext looks unrelated to it. Real RSA uses primes of 1024+ bits each, giving n of 2048 bits or more.

Security and practical details

Breaking RSA ≈ factoring n

If an attacker factors n into p and q, they compute φ(n) and then d, exactly as the key owner did. No efficient classical factoring algorithm is known. 2048-bit n is today's minimum; 3072-bit is recommended for long-term use.

Fast with e = 65537

Exponentiation uses square-and-multiply, needing about one squaring per bit of the exponent. A small public e (65537 = 216+1 is standard) makes encryption and verification fast; decryption with the large d is the slow side.

Never use "textbook" RSA

Raw me mod n is deterministic, so the same message always gives the same ciphertext, and small messages can leak. Real systems add randomized padding: OAEP for encryption and PSS for signatures.

Diffie-Hellman key exchange

Agreeing on a shared secret while someone listens to every word.

Published by Whitfield Diffie and Martin Hellman in 1976, this was the first public demonstration of public key cryptography. It does not encrypt messages itself. It lets two parties who share nothing in advance end up with the same secret number, which they then use as a key for a fast symmetric cipher like AES.

The weakness: man-in-the-middle

Plain Diffie-Hellman gives Alice a shared key with someone, but nothing tells her who. An active attacker, Mallory, who can intercept and replace messages, can run two separate exchanges, one with each side. Step through it:

The fix: authenticate the exchange

Diffie-Hellman must be combined with authentication. In practice each side signs its DH value with a long-term private key whose public key is trusted, usually through a certificate. Mallory can still intercept, but she cannot forge Alice's or Bob's signature on gm, so the substitution is detected. This is how TLS and SSH use Diffie-Hellman.

Ephemeral DH and forward secrecy

If fresh secrets a and b are generated for every session and then deleted, a later theft of the server's long-term signing key cannot decrypt past recorded sessions. This property is called (perfect) forward secrecy, and TLS 1.3 requires ephemeral key exchange.

DH is not encryption

Diffie-Hellman only produces a shared number. It cannot sign and it cannot encrypt by itself; the agreed value is fed into a key derivation function to produce symmetric keys.

04

Digital signatures

Running public key cryptography in reverse: only the private key can sign, anyone can check.

With RSA, the two exponents are interchangeable. Raising to d and then e also gives back the original. So if Alice computes s = md mod n with her private key, anyone can compute se mod n with her public key and check that it equals m. Only the holder of d could have produced s.

Encrypting for confidentiality

Bob's public key Alice encrypts
Bob's private key Bob decrypts

Anyone can send to Bob; only Bob can read.

Signing for authenticity

Alice's private key Alice signs
Alice's public key anyone verifies

Only Alice can sign; everyone can check.

Authentication

Only the private key holder could have produced a valid signature.

Integrity

Changing even one character changes the hash, and verification fails.

Non-repudiation

Unlike a MAC, which uses a shared key both parties hold, only the signer has the private key, so they cannot credibly deny signing to a third party.

05

ElGamal, DSA and elliptic curves

Other algorithms built on the discrete logarithm, and a different kind of "number" that allows much smaller keys.

Discrete log

ElGamal

Extends Diffie-Hellman into encryption and signature schemes. Randomized: the same message encrypts differently every time, and ciphertexts are twice the size of the plaintext.

Discrete log

DSA / DSS

The NIST Digital Signature Algorithm, a variant of ElGamal signatures. Signature only, no encryption. Each signature needs a fresh secret random k; reusing k leaks the private key, as happened with Sony's PlayStation 3 signing keys in 2010.

Elliptic curves

ECDH, ECDSA, Ed25519

The same Diffie-Hellman and DSA ideas, but computed with points on an elliptic curve instead of numbers mod p. Dominant in modern TLS, SSH and messaging apps.

Looking ahead: quantum computers

Shor's algorithm, run on a sufficiently large quantum computer, would efficiently factor integers and solve discrete logarithms, breaking RSA, Diffie-Hellman and ECC alike. No such machine exists yet, but because recorded traffic could be decrypted later ("harvest now, decrypt later"), NIST published post-quantum standards in 2024: ML-KEM (FIPS 203) for key establishment and ML-DSA (FIPS 204) and SLH-DSA (FIPS 205) for signatures. Symmetric ciphers like AES are much less affected; longer keys are enough.

Public key cryptography in practice

Use public key cryptography for the small, hard part, then hand off to a fast symmetric cipher.

Public key operations are far too slow to encrypt bulk data, and secret key cryptography cannot solve key distribution. Real systems combine them, an approach called hybrid encryption. The public key algorithm protects only a short random session key; the session key then encrypts the actual data with AES or a similar cipher, using a mode like the ones covered last lecture.

The remaining problem: whose key is this?

Public keys do not need to be secret, but they do need to be authentic. If Mallory can convince Alice that Mallory's public key belongs to Bob, every guarantee falls apart, exactly as in the man-in-the-middle attack. The standard solution is a certificate: a document binding a name to a public key, digitally signed by a trusted Certificate Authority. Building and managing that trust is the subject of public key infrastructure (PKI).

08

Key takeaways

Before the next lecture
  1. Public key cryptography gives each user a key pair. The public key can be shared openly; the private key never leaves its owner. This solves the key distribution problem that limits secret key cryptography.
  2. Its security comes from trapdoor one-way functions in modular arithmetic: factoring large numbers (RSA) and computing discrete logarithms (Diffie-Hellman, ElGamal, DSA, and their elliptic curve versions).
  3. RSA: n = pq, choose e coprime to φ(n), d = e−1 mod φ(n). Encrypt c = me mod n, decrypt m = cd mod n. Always use padding (OAEP, PSS) in practice.
  4. Diffie-Hellman lets two parties agree on gab mod p over a public channel, but unauthenticated DH is vulnerable to man-in-the-middle attacks. Signing the exchanged values fixes this.
  5. Digital signatures sign a hash with the private key and verify with the public key, giving authentication, integrity and non-repudiation.
  6. ECC offers equal security with much smaller keys. Real systems are hybrid: public key cryptography establishes or wraps a session key, and a symmetric cipher encrypts the data.
