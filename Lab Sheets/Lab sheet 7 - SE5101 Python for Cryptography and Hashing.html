3. Background: Encoding vs Hashing vs Encryption

In Lab 06 (Task 8) you saw that data sent over a plain TCP socket can be read by anyone capturing the traffic. Cryptography gives us tools to protect the three core security goals: Confidentiality, Integrity and Authenticity.

TechniqueReversible?Needs a key?PurposePython example
EncodingYes, by anyoneNoRepresent data in another format (NOT security)base64
HashingNo (one-way)NoIntegrity, fingerprints, password storagehashlib.sha256
HMACNoYes (shared secret)Integrity + authenticity of a messagehmac.new
Symmetric encryptionYes, with the keyYes (same key both sides)ConfidentialityFernet, AESGCM
Asymmetric encryptionYes, with private keyYes (public/private pair)Confidentiality, key exchange, digital signaturesRSA

A good cryptographic hash function has these properties:

  • Deterministic - the same input always gives the same output.
  • Fixed length - SHA-256 always outputs 256 bits, whether the input is 1 byte or 1 GB.
  • Pre-image resistant - given a hash, you cannot work back to the input.
  • Collision resistant - it is infeasible to find two inputs with the same hash.
  • Avalanche effect - a tiny change in input completely changes the output.

4. Part A - Classical Cipher and Encoding

1Caesar Cipher - Encrypt, Decrypt and Brute-Force

The Caesar cipher shifts each letter by a fixed number (the key). Create caesar.py:

def caesar_encrypt(text, shift):
    result = ""
    for ch in text:
        if ch.isalpha():
            base = ord("A") if ch.isupper() else ord("a")
            result += chr((ord(ch) - base + shift) % 26 + base)
        else:
            result += ch          # keep spaces/punctuation
    return result

def caesar_decrypt(text, shift):
    return caesar_encrypt(text, -shift)

secret = caesar_encrypt("Attack at Dawn", 3)
print("Encrypted:", secret)
print("Decrypted:", caesar_decrypt(secret, 3))

# Brute force: try every possible key
print("\n--- Brute force ---")
for key in range(26):
    print(f"Key {key:2}: {caesar_decrypt(secret, key)}")

Run it: python3 caesar.py

What is the ciphertext of "Attack at Dawn" with shift 3?  
How many possible keys does the Caesar cipher have?  
Why was the brute-force attack so easy?  
Tip: ord() turns a character into its number (e.g. ord("A") = 65) and chr() does the reverse. % 26 wraps around so that shifting Z by 1 gives A. Modern ciphers like AES-256 have 2256 possible keys - brute force is impossible.

import hashlib

4The Avalanche Effect

Create avalanche.py:

import hashlib

def sha256_hex(text):
    return hashlib.sha256(text.encode()).hexdigest()

def bits_different(hex1, hex2):
    """Count how many bits differ between two hex digests."""
    x = int(hex1, 16) ^ int(hex2, 16)
    return bin(x).count("1")

a = sha256_hex("hello")
b = sha256_hex("hellp")   # one letter changed
print("hello ->", a)
print("hellp ->", b)
print("Bits changed:", bits_different(a, b), "out of 256")

5File Integrity Checker

Software downloads often publish a SHA-256 checksum so you can confirm the file was not modified. Create file_hash.py:

import hashlib
import sys

def sha256_file(path):
    """Hash a file in 4 KB chunks so large files don't fill memory."""
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for chunk in iter(lambda: f.read(4096), b""):
            h.update(chunk)
    return h.hexdigest()

path = sys.argv[1]
print(sha256_file(path), path)

6. Part C - Password Storage

6Why Plain Hashes Are Weak: A Dictionary Attack

Many breached databases stored passwords as unsalted hashes. Because hashing is deterministic, an attacker can hash a list of common passwords and look for a match. Create crack.py:

import hashlib

# A "leaked" unsalted SHA-256 password hash (from your own test data)
leaked_hash = hashlib.sha256(b"sunshine").hexdigest()

wordlist = ["123456", "password", "qwerty", "letmein",
            "dragon", "sunshine", "monkey", "football"]

for guess in wordlist:
    if hashlib.sha256(guess.encode()).hexdigest() == leaked_hash:
        print("[+] Password found:", guess)
        break
else:
    print("[-] Not in wordlist")
Did the script recover the password?  
If two users both chose sunshine, would their stored hashes be the same?  
Why does that make the attacker's job easier (think "rainbow tables")?  
Tip: The for ... else construct runs the else block only if the loop finishes without hitting break. Real tools such as Hashcat and John the Ripper do the same thing, but test billions of guesses per second on GPUs.
7Salted, Slow Password Hashing with PBKDF2

The fix is to add a random salt (unique per user) and use a deliberately slow key-derivation function. Create password_hash.py:

import hashlib
import hmac
import secrets

ITERATIONS = 600_000

def hash_password(password):
    """Return (salt, hash) using PBKDF2-HMAC-SHA256."""
    salt = secrets.token_bytes(16)
    pw_hash = hashlib.pbkdf2_hmac("sha256", password.encode(), salt, ITERATIONS)
    return salt, pw_hash

def verify_password(password, salt, stored_hash):
    new_hash = hashlib.pbkdf2_hmac("sha256", password.encode(), salt, ITERATIONS)
    return hmac.compare_digest(new_hash, stored_hash)

salt1, h1 = hash_password("sunshine")
salt2, h2 = hash_password("sunshine")   # same password again

print("Salt 1:", salt1.hex(), " Hash 1:", h1.hex()[:32], "...")
print("Salt 2:", salt2.hex(), " Hash 2:", h2.hex()[:32], "...")
print("Same hash for same password?", h1 == h2)

print("Correct password: ", verify_password("sunshine", salt1, h1))
print("Wrong password:   ", verify_password("Sunshine", salt1, h1))
Did the same password produce the same hash twice? Why / why not?  
Time the script with time python3 password_hash.py. How long did it take?  
Why is a slow hash a good thing for passwords but a bad thing for file checksums?  
What to store in a database: the salt and the hash (and the iteration count). The salt is not secret. secrets gives cryptographically secure random bytes - never use the random module for security. hmac.compare_digest() compares in constant time to prevent timing attacks. In production you may also see bcrypt, scrypt or Argon2.

7. Part D - Message Integrity with HMAC

8Detect Tampering with HMAC

A plain hash cannot stop an attacker who changes a message and recomputes its hash. An HMAC mixes in a secret key, so only someone with the key can produce a valid tag. Create hmac_demo.py:

import hmac
import hashlib

key = b"shared-secret-key"
message = b"Transfer 100 to Alice"

tag = hmac.new(key, message, hashlib.sha256).hexdigest()
print("Message:", message.decode())
print("HMAC tag:", tag)

# Receiver recomputes the tag and compares
tampered = b"Transfer 900 to Alice"
for received in [message, tampered]:
    check = hmac.new(key, received, hashlib.sha256).hexdigest()
    ok = hmac.compare_digest(check, tag)
    print(received.decode(), "-> valid?", ok)
Which message passed verification and which failed?  
Change the key on the receiver side only. What happens?  
Does HMAC provide confidentiality (hide the message)?  

8. Part E - Symmetric Encryption

In symmetric encryption, the same key encrypts and decrypts. It is fast and used for bulk data (disk encryption, HTTPS after the handshake, VPNs). The hard part is sharing the key safely.

9Easy, Safe Encryption with Fernet

Fernet is a high-level recipe from the cryptography library. It uses AES-128 in CBC mode plus an HMAC-SHA256, so it gives both confidentiality and integrity with no settings to get wrong. Create fernet_demo.py:

from cryptography.fernet import Fernet, InvalidToken

key = Fernet.generate_key()
print("Key:", key.decode())

f = Fernet(key)
token = f.encrypt(b"Meet at the lab at 10")
print("Ciphertext:", token.decode())

plain = f.decrypt(token)
print("Decrypted:", plain.decode())

# Try decrypting with the WRONG key
wrong = Fernet(Fernet.generate_key())
try:
    wrong.decrypt(token)
except InvalidToken:
    print("[!] Wrong key - decryption failed")

10AES-256-GCM (Authenticated Encryption)

AES-GCM is the mode used in TLS 1.3 and most modern protocols. It needs a nonce ("number used once") for every message. Create aes_gcm.py:

import os
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

key = AESGCM.generate_key(bit_length=256)   # 32-byte key
aes = AESGCM(key)

nonce = os.urandom(12)            # must be unique for every message
plaintext = b"Top secret lab data"
ciphertext = aes.encrypt(nonce, plaintext, None)

print("Key       :", key.hex())
print("Nonce     :", nonce.hex())
print("Ciphertext:", ciphertext.hex())
print("Decrypted :", aes.decrypt(nonce, ciphertext, None).decode())

# Flip one byte of the ciphertext and try again
tampered = bytearray(ciphertext)
tampered[0] ^= 1
try:
    aes.decrypt(nonce, bytes(tampered), None)
except Exception as e:
    print("[!] Tampering detected:", type(e).__name__)
The plaintext is 19 bytes. How many bytes is the ciphertext?  
What are the extra 16 bytes for?  
What exception was raised when one byte was flipped?  
Note: The nonce is not secret and is sent alongside the ciphertext, but you must never reuse a nonce with the same key. Reuse can leak the plaintext and let attackers forge messages. The hazmat ("hazardous materials") part of the library is named that way for a reason - prefer Fernet unless you need a specific algorithm.

9. Part F - Asymmetric Encryption and Digital Signatures

In asymmetric (public-key) cryptography each person has a key pair:

  • The public key can be shared with everyone.
  • The private key is kept secret.
GoalSender usesReceiver uses
Confidentiality (encrypt a message to Bob)Bob's public keyBob's private key
Digital signature (prove Alice wrote it)Alice's private keyAlice's public key
11RSA: Key Pair, Encryption and Signatures

Create rsa_demo.py:

from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import hashes, serialization
from cryptography.exceptions import InvalidSignature

# 1. Generate a key pair
private_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
public_key = private_key.public_key()

pem = public_key.public_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PublicFormat.SubjectPublicKeyInfo)
print(pem.decode())

oaep = padding.OAEP(mgf=padding.MGF1(algorithm=hashes.SHA256()),
                    algorithm=hashes.SHA256(), label=None)

# 2. Encrypt with the PUBLIC key, decrypt with the PRIVATE key
ciphertext = public_key.encrypt(b"Hello Bob", oaep)
print("Ciphertext length:", len(ciphertext), "bytes")
print("Decrypted:", private_key.decrypt(ciphertext, oaep).decode())

# 3. Sign with the PRIVATE key, verify with the PUBLIC key
pss = padding.PSS(mgf=padding.MGF1(hashes.SHA256()),
                  salt_length=padding.PSS.MAX_LENGTH)
document = b"I, Alice, approve this report."
signature = private_key.sign(document, pss, hashes.SHA256())

for doc in [document, b"I, Alice, reject this report."]:
    try:
        public_key.verify(signature, doc, pss, hashes.SHA256())
        print("VALID signature   :", doc.decode())
    except InvalidSignature:
        print("INVALID signature :", doc.decode())
What does the start and end of the PEM public key look like?  
How long is the RSA ciphertext, even though the message was only 9 bytes? Why?  
Which document had a valid signature, and why did the other one fail?  
Tip: RSA is slow and can only encrypt small amounts of data (a 2048-bit key with OAEP-SHA256 can encrypt at most 190 bytes). Real systems use hybrid encryption: RSA (or Diffie-Hellman) exchanges a random AES key, then AES encrypts the actual data. This is exactly what HTTPS does.

12Encrypted TCP Client/Server (links to Lab 06)

Step 1 - create a shared key file with make_key.py:

from cryptography.fernet import Fernet

key = Fernet.generate_key()

    f.write(key)

Step 2 - secure_server.py:

import socket
from cryptography.fernet import Fernet

HOST = "127.0.0.1"
PORT = 5001

with open("secret.key", "rb") as f:
    cipher = Fernet(f.read())

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
server.bind((HOST, PORT))
server.listen(1)
print(f"[*] Secure server listening on {HOST}:{PORT}")

conn, addr = server.accept()
print(f"[+] Connection from {addr}")

while True:
    data = conn.recv(4096)
    if not data:
        break
    print("[<] Raw bytes on the wire:", data[:40], "...")
    message = cipher.decrypt(data).decode()
    print("[<] Decrypted message   :", message)
    reply = cipher.encrypt(f"Server got: {message}".encode())
    conn.sendall(reply)

conn.close()
server.close()

Step 3 - secure_client.py:

import socket
from cryptography.fernet import Fernet

HOST = "127.0.0.1"
PORT = 5001

with open("secret.key", "rb") as f:
    cipher = Fernet(f.read())

client = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
client.connect((HOST, PORT))
print(f"[*] Connected to {HOST}:{PORT} (type 'quit' to exit)")

while True:
    message = input("You: ")
    if message.lower() == "quit":
        break
    client.sendall(cipher.encrypt(message.encode()))
    reply = client.recv(4096)
    print(cipher.decrypt(reply).decode())

client.close()
