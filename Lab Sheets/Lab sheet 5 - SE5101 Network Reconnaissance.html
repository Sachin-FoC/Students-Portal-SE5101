SE5101 – Computer and Network Security

Lab Sheet 05: Network Reconnaissance

Duration: 2.5–3 hours  |  Environment: Kali Linux VM + one or more Target VMs (Host-Only network)  |  Mode: Individual / Pair  |  Level: Beginner (builds on Lab 04)

1. Learning Outcomes

By the end of this lab, students will be able to:
  • Explain the difference between passive and active reconnaissance and where each sits in the attacker "kill chain".
  • Discover live hosts on a subnet using ARP scanning and ICMP/ping sweeps.
  • Perform TCP and UDP port scans with nmap and interpret open / closed / filtered states.
  • Enumerate running services and their versions, and attempt basic OS fingerprinting.
  • Grab service banners manually with netcat and telnet.
  • Run simple Nmap Scripting Engine (NSE) scripts for safe enumeration.
  • Correlate what a scan looks like on the wire by capturing it in Wireshark (linking back to Lab 04).

2. Pre-Lab Setup

  • ☐ Kali Linux VM and at least one target VM (e.g. Metasploitable 2/3, a Linux server VM, or your peer's VM) on the same Host-Only network (see Lab Sheet 03).
  • ☐ Confirm connectivity with ping before starting, and note your own IP/subnet: 
    ip a
ping -c 3 <target-VM-IP>
  • ☐ Verify the tools are present (all ship with Kali): 
    nmap --version
netdiscover --help | head -n 3
nc -h 2>&1 | head -n 3
    If nmap is somehow missing: 
    sudo apt update && sudo apt install nmap netcat-traditional -y
  • ☐ Create a folder to keep your output files in one place: 
    mkdir -p ~/lab05_recon && cd ~/lab05_recon
⚠ Ethics & Legal Notice: Scanning is only to be performed against the isolated Host-Only lab targets you have been assigned or your own VMs. Never scan university infrastructure, public IP addresses, cloud hosts, websites, or any machine you do not own or have written permission to test. Unauthorised port scanning is treated as hostile activity and is a criminal offence in most jurisdictions (e.g. under computer-misuse legislation). When in doubt, don't scan it.

3. Background: What Is Reconnaissance?

Reconnaissance is the information-gathering phase - building a picture of the target before any exploitation is attempted. It is usually split into two types:

TypeDescriptionExample techniques
PassiveGather information without sending traffic directly to the target - the target sees nothing.WHOIS lookups, public DNS records, search engines, certificate transparency logs
ActiveInteract directly with the target; this generates traffic the target could log or detect.Host discovery, port scanning, version detection, banner grabbing

This lab focuses mainly on active reconnaissance inside the safe lab network, with a short passive component. The logical progression is:

Discover live hosts  →  Find open ports  →  Identify services & versions  →  Fingerprint the OS

Nmap port states you will meet:
StateMeaning
openAn application is actively accepting connections on that port.
closedPort is reachable but nothing is listening (host responded, port shut).
filteredNmap can't tell - a firewall/filter is dropping the probes.
open|filteredNmap can't decide between open and filtered (common with UDP).

2Host Discovery - ARP Scan

On a local/Host-Only segment, ARP is the most reliable way to find live hosts (it can't be blocked by a host firewall the way ICMP can).

  1. Run an ARP sweep of your subnet with netdiscover (passive/active) - replace the range with yours: 
    sudo netdiscover -r 192.168.56.0/24
    Press Ctrl+C after a few seconds once hosts appear.
  2. Or use Nmap's ARP-based host discovery (no port scan, -sn): 
    sudo nmap -sn 192.168.56.0/24
  3. List every live host you found.

3Basic TCP Port Scan

Now focus on your single target. Start with a default Nmap scan of the most common 1000 TCP ports.

nmap <target-IP>

Then run a faster explicit SYN ("half-open") scan, which needs root:

sudo nmap -sS <target-IP>

Tip: -sS (SYN scan) sends a SYN and, on getting SYN-ACK, replies with RST instead of completing the handshake - so the connection is never fully established. Compare this with the full three-way handshake you saw in Lab 04.
4Wider & UDP Scans

    sudo nmap -p- <target-IP>
  2. Scan a few common UDP ports (UDP scans are slow and often show open|filtered): 
    sudo nmap -sU --top-ports 20 <target-IP>

5Service & Version Detection

Knowing a port is open is not enough - you want to know what is running and its version (this is what drives vulnerability lookups later in the module).

sudo nmap -sV <target-IP>

For a more aggressive combined scan (version + default scripts + OS + traceroute):

sudo nmap -A <target-IP>

7Manual Banner Grabbing

Many services announce themselves when you connect. Grab a banner by hand - no Nmap required.

  1. Using netcat against an open TCP port (try SSH on 22 or a web server on 80): 
    nc <target-IP> 22
  2. For an HTTP banner, connect and issue a minimal request: 
    nc <target-IP> 80
HEAD / HTTP/1.0
    (type the HEAD line, then press Enter twice)
  3. You can also try telnet <target-IP> 21 against an FTP port.

8Nmap Scripting Engine (NSE)

NSE adds ready-made enumeration scripts. Use only safe, default-category scripts in this lab.

  1. Run the default script set against open ports: 
    sudo nmap -sC <target-IP>
  2. Try a specific, harmless enumeration script, e.g. HTTP title or SSH host key: 
    nmap --script http-title <target-IP> -p 80
nmap --script ssh-hostkey <target-IP> -p 22

9See the Scan on the Wire (Wireshark link-back)

Tie this lab to Lab 04: capture your own scan traffic and observe what scanning actually looks like.

  1. Start a Wireshark capture on the Host-Only interface (as in Lab 04).
  2. In a terminal, run a small SYN scan of a handful of ports: 
    sudo nmap -sS -p 20-25,80,443 <target-IP>
  3. Stop the capture. Apply a display filter to see the scan probes: 
    tcp.flags.syn == 1 && tcp.flags.ack == 0
  4. Notice the burst of SYN packets to many ports, and how open ports reply with SYN-ACK while closed ports reply with RST.
